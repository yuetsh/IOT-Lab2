# Admin Summary 页面重设计

**日期**: 2026-05-14  
**目标**: 将现有数据展示页面改造为面向大屏投影的教学评价页面，体现学生在功能设计与设备选型两个维度的学习成效。

---

## 背景

现有 AdminSummary 页面包含多个图表（条形图、雷达图、检测矩阵、时间线），信息散乱，无法清晰体现学习评价。教师需要一个在课堂大屏上直观展示的评价视图，学生能快速定位自己小组的成绩。

## 评价维度

| 维度 | 数据来源 | 含义 |
|------|---------|------|
| 功能设计 | 流程图检测 (check_runs) | 学生设计各区域安防流程图的质量 |
| 设备选型 | 设备放置检测 (device_check_results) | 学生在平面图上选择并放置设备的准确度 |

每个维度展示三个指标：
- **最终通过率** — 该维度最后一次检测的通过率
- **进步幅度** — 第一次检测通过率 → 最后一次通过率的差值
- **完成覆盖度** — 6个区域中已完成的数量

## 页面布局（从上到下）

### 第一层：班级总览数字条

一行 4 个指标：
- 参与小组数
- 功能设计班级平均通过率
- 设备选型班级平均通过率
- 全区域完成的小组数

### 第二层：小组卡片墙

- **布局**: 固定 2 列网格
- **每张卡片**: 显示小组名称，内部左右两列分别展示功能设计和设备选型
- 每列内容：
  - 最终通过率（带进度条，颜色：≥80% 绿、≥60% 黄、<60% 红）
  - 进步幅度（带 + 号标注）
  - 6个区域点阵（绿=通过、黄=未通过、灰=未完成）
- 最优小组卡片加金色边框高亮

### 第三层：功能设计分析块

标题："功能设计成效"

两列并排：
- **左**: 各小组最终通过率横向条形图（按通过率降序排列）
- **右**: 各小组 × 6区域 完成覆盖矩阵（✓通过 / △进行中 / ✗未通过 / —未完成）

### 第四层：设备选型分析块

标题："设备选型成效"

两列并排：
- **左**: 各小组最终通过率横向条形图（按通过率降序排列）
- **右**: 各小组进步幅度横向条形图（首次 → 最终）

---

## 删除的现有图表

| 图表 | 删除原因 |
|------|---------|
| 各区域平均通过率雷达图 | 面向区域难度分析，不体现学生学习成效 |
| 小组活跃度条形图 | 与评价无关，仅反映操作频次 |
| 完成时间线 | 信息密度低，大屏展示意义不大 |

---

## 数据接口

使用现有接口：
- `GET /api/admin/summary` — 提供 overview（总览数字）+ groups（每组区域通过率数据）
- `GET /api/admin/progress` — 提供 checkTrend（各组各区域各轮检测记录）+ completionTimeline

计算逻辑（前端）：
- **最终通过率**: 取 `latest_check_passed / latest_check_total`
- **进步幅度**: 取 checkTrend 中该组该维度第一次 vs 最后一次检测通过率的差
- **覆盖矩阵**: 根据 completed_areas 和 check_runs 判断每个区域状态

无需新增后端接口。

## 组件结构

```
AdminSummary.tsx
├── SummaryBar           # 第一层：4个总览数字
├── GroupCardGrid        # 第二层：小组卡片墙（2列）
│   └── GroupCard        # 单张卡片
│       ├── DimBlock     # 功能设计列
│       └── DimBlock     # 设备选型列
├── AnalysisBlock        # 第三层：功能设计分析（可复用）
│   ├── PassRateChart    # 通过率条形图
│   └── CoverageMatrix   # 区域覆盖矩阵
└── AnalysisBlock        # 第四层：设备选型分析（复用）
    ├── PassRateChart    # 通过率条形图
    └── ImprovementChart # 进步幅度条形图
```

## 成功标准

1. 页面在 1920×1080 大屏上无需滚动即可看到卡片墙全貌
2. 学生能在 3 秒内找到自己组的卡片
3. 通过率颜色编码直观（不需要图例即可理解好/中/差）
4. 现有后端接口无需改动
